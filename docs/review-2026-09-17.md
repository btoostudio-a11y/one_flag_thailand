# Game review — 2026-09-17

Scope: standalone fork, working changes from b89ce41. Specification: play as Guest,
save server-calculated score, optionally verify email/login and claim existing scores.
Main-site UI was not modified. Reviews ran independently for Standards and Spec.

## Standards

Two P2 findings, both fixed: a failed hit request disabled all subsequent scoring;
the saved-score shortcut could lead to an indefinite saving state for an unfinished round.
Later live hits now continue with an explicit partial-input warning. Saved-score recovery
uses confirmed round capabilities, a real result fetch, and loading/error/empty states.

Nonblocking design judgments: SupabaseClient currently combines auth, transport and
round lifecycle; split these if complexity increases. The legacy estimate_rank adapter
returns zero and is not used as a displayed public rank.

## Spec

Four P2 findings fixed:
1. Recover later hits after network failure and disclose unconfirmed inputs.
2. Restore saved scores with real fetch/retry, including after account claim.
3. Ignore stale refresh responses after a newer login/logout.
4. Disable navigation while logout is pending.
A follow-up source review found no remaining blockers among these findings.
Startup result fetches are also prevented from overwriting a newly started round.

## Security

No confirmed client privilege escalation or secret exposure in reviewed source.
Browser roles cannot read/write round tables or call scoring RPCs. Claims verify the
Auth user and confirmed email; locked rows prevent ownership takeover and duplicate
finalization. Guest capabilities use cryptographic random bytes and are stored hashed
on the server. Claimed scores are not accepted by the API. Scanned 47 source/config files
for secret-key/PAT/private-key patterns without matches.

Remaining limits:
- Security Advisor reports leaked-password protection disabled in shared Supabase Auth.
- Per-IP round limiting depends on the deployment's X-Forwarded-For trust boundary;
  do not treat it as verified anti-abuse enforcement before checking the deployed gateway.
- Legal automated taps remain possible. Server score verification is not human/bot proof.
- Guest capabilities and refresh sessions rely on this device's local storage.
- Actual SMTP delivery and desktop/mobile WebGL interaction require manual verification.

## Validation

Passed Godot offline smoke, SaveFlow/recovery regressions and Web export.
Passed live Edge/API Guest score persistence, idempotency, verified account claim and
public account leaderboard. Passed native Godot full round (100 points) and login/claim.
Disposable API/Godot test accounts and rounds were removed without sending email.
SQL ownership/privilege tests passed previously; no database schema changed in this review.
Final source changes are client recovery fixes; deployed Edge logic remains unchanged.

Standards: 2 correctness findings fixed; 2 nonblocking design judgments.
Spec: 4 findings fixed; no remaining blocker found in the reviewed recovery scope.
